🗺️ Bản Đồ Tác Chiến: Module Identity

Mục tiêu: Đăng ký, Đăng nhập, Băm mật khẩu (Bcrypt) và Cấp phát JWT Token.

🏗️ Trình tự 4 Tầng (Clean Architecture)

Chúng ta sẽ code từ LÕI (Domain) đi dần ra BỀ MẶT (Endpoints). Không bao giờ được phép làm ngược lại.

1. Tầng Domain (Lõi)

Nơi định nghĩa các Thực thể (Entities) cốt lõi nhất. Tầng này "mù tịt" về Database hay API, nó chỉ chứa logic kinh doanh tinh khiết.

  • User.cs: Kế thừa từ AggregateRoot (đã làm ở Giai đoạn 0). Có các thuộc tính: Email, PasswordHash, Role.
  • Luật: Trạng thái của User chỉ được phép thay đổi thông qua các hàm có ý nghĩa (ví dụ: ChangePassword()) thay vì dùng Setters set; trực tiếp.

2. Tầng Application (Ứng dụng)

Chứa các Use-Cases (Mục đích sử dụng). Áp dụng triệt để kiến trúc CQRS (Giai đoạn 0).

  • Đăng ký: RegisterUserCommand & RegisterUserCommandHandler.
  • Đăng nhập: LoginQuery & LoginQueryHandler.
  • Giao diện: IUserRepository (Chỉ tạo interface ở đây, bắt Infrastructure code logic thực tế).

3. Tầng Infrastructure (Hạ tầng)

Nơi giao tiếp thực tế với thế giới bên ngoài (Database MySQL, Thuật toán Băm mật khẩu).

  • IdentityDbContext: Cấu hình Entity Framework Core ánh xạ class User thành bảng users trong MySQL.
  • UserRepository.cs: Code các câu lệnh SQL/LINQ để tìm kiếm User theo Email.
  • PasswordHasher.cs: Dùng thư viện BCrypt để băm nát mật khẩu trước khi lưu.

4. Tầng Endpoints (Cổng giao tiếp)

Nơi bóc tách các Request HTTP từ Client (React/Mobile) gửi tới và ném vào tầng Application xử lý.

  • Sử dụng Carter thay cho Controllers cũ kỹ. Giúp định nghĩa API cực kỳ ngắn gọn.
  • API Đăng ký: POST /api/identity/register
  • API Đăng nhập: POST /api/identity/login
